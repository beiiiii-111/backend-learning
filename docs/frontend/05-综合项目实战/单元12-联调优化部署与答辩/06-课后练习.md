# 单元 12 课后练习

> 模块五 · 综合项目实战 › 单元 12

这是这门课最后一次练习。**目标不是学新东西，是把已有的成果交付出去。**

练习分三部分：

- **必做**

  ：交付的四个硬性要求，缺一个都会影响最终评分。
- **选做**

  ：让项目从“作业”变成“作品”的加分项。
- **长期**

  ：课程结束后可以继续做的事。

## 必做 1：完成一次前后端联调并记录

### 要求

把前端接到真实后端（或同学写的后端、或 `json-server` 等模拟服务），跑通下面这条链路：

```
登录 → 活动列表 → 新增活动 → 列表里看到新活动 → 下架活动 → 状态变化
```

写一份联调记录表，保存为 `docs/dev-notes.md` 的一部分。

### 验收标准

| 检查项 | 通过标准 |
| --- | --- |
| 链路完整跑通 | 五步都能操作成功 |
| 记录表至少 5 条 | 每条包含现象、排查过程、定位、处理 |
| “排查过程”有内容 | 写清了试过什么、排除了什么，不是直接写结论 |
| 至少一条用的是工具复现 | 记录里能出现 curl 命令或 Postman 的请求信息 |
| 记录了字段核对的结果 | 统一响应结构、分页字段、时间格式三件事都有结论 |
| 记录了 token 的处理方式 | 存哪里、怎么带、401 怎么处理 |

## 必做 2：完成构建优化并给出对比数据

### 要求

按 [12.2](02-12.2-构建优化.md) 的优先级顺序逐项优化，每做一项测一次数据，填进对比表。

### 验收标准

| 检查项 | 通过标准 |
| --- | --- |
| 有基线数据 | 优化前的 dist 大小、首屏 transferred、请求数都有 |
| 至少做了 4 项优化 | 从路由懒加载、按需引入、分包、压缩、图片优化里选 |

| 首屏传输量下降 50% 以上 | 如果没达到，分析原因 |
| 有结论 | 说清哪项贡献最大、哪项没效果 |

## 必做 3：部署上线，得到可访问的地址

### 要求

把项目部署到一个**别人也能访问**的地址上。

### 验收标准

| 检查项 | 通过标准 |
| --- | --- |
| 地址不是 localhost | 必须是公网可访问的地址 |
| 首页能打开 | 换个浏览器（或无痕窗口）打开正常 |
| **子路由刷新不 404** | 在 `/activity` 页面按 F5，页面正常 |
| **深链接能直接打开** | 地址栏直接输入 `/activity`，页面正常 |
| 接口能通 | 线上能完成登录和查询 |
| 有 HTTPS | 地址栏有锁标志，控制台没有混合内容警告 |
| 手机能访问 | 用手机浏览器打开正常 |
| 静态资源被压缩 | 响应头有 `Content-Encoding: gzip` 或 `br` |
| 静态资源走缓存 | 刷新后 JS 显示 `from disk cache` |
| `index.html` 不缓存 | 响应头有 `no-cache` 或 `no-store` |
| 有部署文档 | 按文档能从头部署一遍 |

## 选做 1：写一个自动部署脚本

### 要求

把部署过程写成一个脚本，一条命令完成。要求：

- 有前置检查（工作区是否干净、构建是否成功）
- 有备份机制（出问题能回滚）
- 失败时立即退出，不带着错误继续

### 验收标准

| 检查项 | 通过标准 |
| --- | --- |
| 一条命令完成部署 | 执行脚本后线上自动更新 |
| 有工作区检查 | 有未提交改动时会阻止部署并提示 |
| 有备份 | 部署前备份了当前线上版本 |
| 有失败退出 | 中间任何一步失败都会停下来 |
| 有回滚方法 | 文档里写了怎么用备份恢复 |
| 脚本里有注释 | 每一步在做什么能看懂 |

## 选做 2：给项目加上持续的代码质量保障

### 要求

在仓库里加上自动检查，让问题在提交时就暴露。

- 提交前跑 ESLint 和 Prettier（只检查改动过的文件）
- 提交信息符合 Conventional Commits
- 推送后自动跑一次构建，构建失败会有通知

### 验收标准

| 检查项 | 通过标准 |
| --- | --- |
| 提交前自动检查 | 故意写一行不合规范的代码，提交被拦下 |
| 只检查改动的文件 | 提交时不会因为别人文件的旧问题被拦 |
| 提交信息有校验 | 写“update”这样的信息会被拒绝 |
| 推送后有自动构建 | 在仓库的 Actions 页面能看到构建记录 |
| 构建失败有反馈 | 故意推一个语法错误的提交，能看到失败记录 |

## 选做 4：做一次完整的故障演练

### 要求

故意制造六种故障，逐个排查，记录现象和定位方法。

| 编号 | 制造什么故障 |
| --- | --- |
| 1 | 注释掉 Nginx 的 `try_files` |
| 2 | 把 `.env.production` 的接口地址改成 `http://localhost:8080` |
| 3 | 把 `base` 改成 `'/wrong/'` |
| 4 | 注释掉 `index.html` 的不缓存配置 |
| 5 | 去掉 axios 的超时配置，把后端停掉 |
| 6 | 在 `proxy_pass` 后面加一个斜杠 |

### 验收标准

| 检查项 | 通过标准 |
| --- | --- |
| 六种故障都复现了 | 每种都有现象记录 |
| 记录了控制台报错 | 不是只写“打不开” |
| 记录了 Network 表现 | Status、请求地址、响应头 |
| 有定位方法 | 看到什么现象能推出是哪个问题 |
| 有排查时间记录 | 第一次多久，之后多久 |

## 长期：课程结束之后

这门课在单元 12 结束了，但项目不用停。下面这些事值得在课程结束后继续做。

### 补齐没做的功能

从“已知问题”里挑一个做掉。**优先级建议**：

| 优先级 | 功能 | 为什么 |
| --- | --- | --- |
| 高 | 报名的候补队列 | 真实场景里名额满是最高频的诉求 |
| 高 | 操作日志 | 审核记录不留痕，出问题无法追溯 |
| 中 | 场次的准备时间 | 让冲突检测更贴近真实场景 |
| 中 | 数据导出（Excel） | 老师最常问的需求 |
| 低 | 移动端适配 | 管理端主要在电脑上使用 |

### 换一个技术点重做一遍

同一个项目，换一种实现方式，对比两种做法的差别。这是提升技术判断力最快的办法。

| 换什么 | 能学到什么 |
| --- | --- |
| 把 Element Plus 换成自己写的组件库 | 组件设计的思路 |
| 把 axios 换成 `fetch` 封装 | 网络层的本质 |
| 加上 TypeScript | 类型系统怎么帮你提前发现问题 |
| 加上单元测试（Vitest） | 怎么测一个组件的行为 |
| 加一个 Node 中间层（BFF） | 前后端职责怎么划分 |

### 把它变成作品

- 把仓库设为公开，写清 README，加上截图或动图
- 在 README 里放线上地址和测试账号
- 把这个项目放进你的简历和 GitHub Profile

**做完这一步，你的简历里就有一句可以验证的话**：“独立完成一个校园活动管理后台，含登录鉴权、活动管理、报名审核、场次安排四个模块，已部署上线（附地址）。”

**这句话比“熟悉 Vue 3、了解前端工程化”有说服力得多。** 因为它可以被打开、被使用、被验证。

### 下一步学什么

按[学习路线的第三阶段](../../00-课程导学/04-前端学习路线.md)，五个方向里挑一个深入：

| 方向 | 下一步学什么 |
| --- | --- |
| 业务开发 | TypeScript、组件库设计、性能监控 |
| 跨端开发 | uni-app、小程序原生开发、跨端调试 |
| 服务端渲染 | Nuxt 3、SEO、首屏性能 |
| 质量与工程 | 单元测试、端到端测试、CI/CD、monorepo |
| 可视化 | ECharts、D3、WebGL、大屏适配 |

**不要五个方向都学。** 挑一个，用三个月做深。**这个项目已经给了你一个真实的练习场 —— 把新的技术用在这个项目上，比另起一个 demo 学得快。**
