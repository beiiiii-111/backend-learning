> 附录

这五份附录是教程的"工具区"。正文按顺序讲知识，附录按**你此刻遇到的问题**来查。

- 写着写着忘了某个 API 怎么写 → 翻速查手册。
- 终端报了一个看不懂的错 → 翻常见报错与排查。
- 不确定某个包该装哪个版本、某个工具是干什么的 → 翻工具链与版本清单。
- 要用 AI 写代码，但不确定怎么描述、怎么审 → 翻AI 编程工具速查。
- 两个概念傻傻分不清（比如"打包"和"编译"）→ 翻术语表。

### 使用建议

- **速查手册不要通读**

  。它是字典，不是教材。写代码时遇到"这个怎么拼"就查一下，
  几次之后自然就记住了。
- **报错排查要按顺序做**

  。每一条都按"现象 → 原因 → 解决 → 怎么预防"写，
  先看现象对不对得上，再看原因，别跳过原因直接抄解决命令。**抄命令能解决一次，看懂原因能解决一类。**
- **版本清单在新建项目时对照一遍**

  。版本不对会引出一批莫名其妙的报错，
  一开始就用基线版本最省事。
- **术语表适合"读文档前预习"**

  。很多英文文档读不懂不是英语问题，
  是术语没对上。先在术语表里找一遍，读起来会顺很多。

**附录也是可以提意见的**

如果你遇到的报错不在[常见报错](02-常见报错与排查.md)里，
或者某条排查步骤看完还是不懂，记下来告诉老师。
**下一版的附录就靠这些反馈补全。**

## 怎么用这套附录配合正文

举一个真实的排查流程，你会看到附录之间怎么配合：

1. 终端报Failed to resolve import "@/stores/auth"。
2. 翻常见报错，在"Vite 与构建类"里找到这一条，
  按"现象 → 原因"定位到是**路径大小写**

  或**别名没配**

  。
3. 按"解决"里的命令检查，同时去工具链清单确认 Vite 版本与别名配置写法。
4. 修好后，在术语表里确认自己理解了"路径别名"是什么，
  下次遇到类似的报错能自己判断。

**排查一次，把这一类问题的原因搞懂，比记住十条命令有用。**
