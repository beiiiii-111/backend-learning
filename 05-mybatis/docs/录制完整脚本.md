## 0. 开录前的准备（不录进视频）

### 0.1 屏幕与字体

- 布局：**左半屏 IDEA，右半屏 Apifox**；段 4 时右半屏切成终端
- IDEA：`View → Appearance → Enter Presentation Mode`；字号用 `Ctrl+Shift+A` 搜 `Increase Font Size` 放大到 18px 以上
- Apifox：右下角缩放调到 125%，让响应 JSON 看得清
- 关掉微信/钉钉弹窗通知，关掉不相关的标签页

### 0.2 停掉旧实例、确认配置

8005 端口必须只有一个实例，否则你改了配置重启不生效（昨晚就是这么翻车的）：

```powershell
Get-CimInstance Win32_Process -Filter "Name='java.exe'" |
  Where-Object { $_.CommandLine -like '*top.yixz.mybatis*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Start-Sleep -Seconds 3
Get-NetTCPConnection -LocalPort 8005 -State Listen -ErrorAction SilentlyContinue   # 无输出 = 干净
```

打开 `src/main/resources/application.yml`，确认是 **`10` / `5`**（段 4 才会临时改成 1）：

```yaml
      maximum-pool-size: 10     # 池上限
      minimum-idle: 5           # 空闲保底连接数
```

### 0.3 启动应用

```bash
cd /d/backend-learning
~/.trae-cn/tools/maven/latest/bin/mvn -pl 05-mybatis spring-boot:run
```

等到日志出现 **`Started MybatisApplication`** 再开始（首次 20~40 秒）。

### 0.4 冒烟（确认活着）

```bash

curl -s http://localhost:8005/courses         # 3 条：id 1,2,3
```

### 0.5 Apifox 环境确认

右上角环境下拉 → 确认指向 `http://localhost:8005`。**这一步不确认，后面全是 404。**

### 段 1 · 基础 1：LambdaUpdateWrapper 改邮箱（约 1 分 30 秒）

**前置**：应用刚启动，用户数据是初始的

**操作**：

1. IDEA 打开 `service/impl/UserServiceImpl.java`，光标停在 `modifyEmailByUsername`
2. 切 Apifox，点 `GET getById` → 路径参数 id 填 **2** → 发送 → **指着响应里的 email 记住它**
3. 点 `PUT 课后基础1：LambdaUpdateWrapper 按 username 更新邮箱` → Query 填：
   - `username` = `zhangsan`
   - `email` = `zhangsan_new@example.com`
   - 发送 → 返回 `true`
4. 回到 `GET getById`（id=2）→ **重新点一次发送** → email 变了，`updateTime` 也变了

**台词**：
> 这里用的是 `LambdaUpdateWrapper`，条件是 `User::getUsername` 这种方法引用，不是字符串——
> 将来改字段名编译器会直接报错，写 `"username"` 就不会。
> 对比 `updateById`，那个只能按主键改，还得先把整条记录查出来。
> （指着 `.set(User::getUpdateTime, ...)` 那行）这行是我踩坑加的，最后总结时说。

**预期结果**：email `zhangsan@example.com` → `zhangsan_new@example.com`，`updateTime` 变化；控制台 SQL：
`UPDATE t_user SET email=?, update_time=? WHERE username=? AND deleted=0`

**翻车**：
- email 已经是 `zhangsan_new@...` → 换个值，比如 `zhangsan_v2@example.com`
- 想复原 → 重启应用

### 段 2 · 基础 2：@JsonFormat（约 1 分 30 秒）

**操作**：

1. IDEA 打开 `entity/User.java`，从上往下划过 5 个时间字段的注解
2. Apifox：`GET getById` → id 填 **1** → 发送 → 指着响应里的
   `birthday` / `workTime` / `lastLoginTime` / `createTime` / `updateTime`
3. **输入侧验证**：Apifox 点 `POST 新增` → **Body → JSON**，粘贴（**你现在那个 Body 是空的，必须填**）：
   ```json
   {"username":"zhouba","age":28,"birthday":"1997-05-20","workTime":"09:00:00","lastLoginTime":"2026-10-10 20:00:00"}
   ```
   发送 → 返回 `true`（或新 id）

**台词**：
> DATE 对应 `yyyy-MM-dd`，TIME 对应 `HH:mm:ss`，DATETIME 对应 `yyyy-MM-dd HH:mm:ss`。
> 输入侧同样生效——（指着刚发的请求）我传的是空格分隔的 SQL 风格字符串，也能解析落库。
> 不加注解的话 Jackson 只认带 T 的 ISO 格式。
> `score` 不加，因为 `@JsonFormat` 的 pattern 是给日期用的，它是浮点评分，加了没意义；
> 顺带一提，如果是金额就不能用 FLOAT，得用 DECIMAL 配 BigDecimal。

**预期结果**：`"birthday":"1995-01-15"`、`"workTime":"09:00:00"`、`"createTime":"2026-10-01 09:00:00"`，POST 返回成功

**翻车**：`zhouba` 已存在 → 换成 `zhouba2`；想彻底复原 → 重启应用

### 段 3 · 进阶 1：t_course + saveBatch / removeByIds（约 2 分钟）

**操作**：

1. IDEA 打开 `resources/schema.sql`，滚到 `t_course` 那段，讲类型选型
2. 打开 `service/impl/CourseServiceImpl.java`，讲 `saveBatch` 批次刷写（默认 1000 条一批）+ 外层事务
3. Apifox → `POST 批量新增：saveBatch` → **Body → JSON**：
   ```json
   [{"name":"操作系统","teacher":"赵老师","credit":3.0},{"name":"计算机网络","teacher":"钱老师","credit":2.5}]
   ```
   发送 → 返回 **2**
4. `GET list` → **重新点发送** → **5 条**，新增的两条是 **id 4、5**
5. `DEL 移除：removeByIds` → Query 填 `ids` = **`4,5`** → 发送 → `true`
6. **回到 `GET list` 再点一次发送**（Apifox 不会自动刷新！）→ 3 条

**台词**：
> 学分用 `DECIMAL(3,1)`，因为可能出现 2.5 这种半学分，是精确小数，不能用 FLOAT。
> 这张表我**故意没加 deleted 字段**，所以这里的删除是真的 DELETE，和用户表的逻辑删除形成对照。
> （指着响应）`createTime` 有值，但我代码里从没 set 过，是 `MetaObjectHandler` 自动填充的。

**预期结果**：3 条 → 5 条（credit 输出 2.5 / 3.0，精度没丢）→ 删完 3 条；
控制台打印的是一条批量 INSERT：`INSERT INTO t_course (...) VALUES (...),(...)`

**翻车**：
- 新增出来的 id 不是 4、5 → 说明没重启，用实际 id 填 `ids`，**或者干脆重启重录**
- 删完 list 还显示 5 条 → **你没重新点发送**，Apifox 展示的是上一次响应
- 返回 `false` 而不是 `true` → id 填错了，那两条根本不存在

### 段 4 · 进阶 2：连接池耗尽（约 2 分 30 秒）

这段要**改配置重启两次**，拆成 4-1 / 4-2 / 4-3 录，重启等待剪辑时剪掉。

#### 4-1 讲代码 + 改配置（约 50 秒）

1. IDEA 打开 `application.yml`，鼠标指着 `maximum-pool-size: 10`
2. 打开 `UserServiceImpl.slowQuery`，讲：
   > 关键是 `@Transactional`——方法里第一条 SQL 借走连接，方法结束（提交或回滚）才归还。
   > 所以 sleep 这 5 秒里连接是被攥着的，别的请求只能排队。
3. **镜头内手动改成 1**：
   ```yaml
         maximum-pool-size: 1      # 池上限
         minimum-idle: 1           # 空闲保底连接数
   ```
4. 终端 `Ctrl+C` → 重启 → **等 `Started MybatisApplication`**（⏸ 这里暂停录制）

#### 4-2 复现报错（约 50 秒）

切到终端（右半屏换成终端）：

```bash
bash scripts/pool-demo.sh 5 5000
```

约 6~8 秒跑完，**逐条念结果**：

```
请求 1: HTTP 200, 耗时约 6s
请求 2: HTTP 500, 耗时约 4s  Could not open JDBC Connection for transaction
请求 3~5: 同上
```

**必须强调**：
> 注意失败请求耗时是 **3 秒左右**，也就是 `connection-timeout: 3000`，**不是 5 秒**。
> 这说明它们是"等连接"超时，不是"执行慢"。底层异常是
> `SQLTransientConnectionException: Connection is not available, request timed out after 3000ms`。

#### 4-3 调回默认值对照（约 50 秒）

1. 把 yml 改回 `10` / `5`
2. 重启（⏸ 暂停录制）
3. 再跑一次 `bash scripts/pool-demo.sh 5 5000` → **5 个全 200**

> 池够用时并发不排队，这是对照组的意义。

**⚠️ 这段录完必须确认 yml 是 `10` / `5`**，否则后面订单演示会莫名报连接池错。

**翻车**：
- 池=1 时 5 个全成功 → 配置没生效，看日志有没有 `Started MybatisApplication`（多半是旧进程没杀干净）
- 脚本报 command not found → 确认在 `/d/backend-learning` 目录下，或用绝对路径
  `bash /d/backend-learning/05-mybatis/scripts/pool-demo.sh 5 5000`

### 段 5 · 挑战：订单事务原子性（约 2 分 30 秒）

**操作**：

1. IDEA 打开 `schema.sql` 的 `t_order` / `t_product`，讲 `amount DECIMAL(12,2)`
2. 打开 `service/impl/OrderServiceImpl.java`，讲三步顺序：
   > 故意**先 insert 再校验库存**。如果先校验，订单还没写进去就抛异常了，根本看不出回滚发生过。
   > 先写再抛，才能证明"已经执行的写操作被撤销"。
3. Apifox：
   - `GET 商品 getById` id=1 → 发送 → **stock = 10**
   - `POST 创建订单` → Query 填 `userId=1`、`productId=1`、`quantity=2` → 发送
     → 指着响应讲 `orderNo`、`amount`、`status=0`、`createTime` 自动填充、`deleted=0`
   - `GET 商品 getById` id=1 → **重新发送** → **stock = 8**
4. 失败路径：
   - `POST 创建订单` → `quantity` 改成 **999** → 发送 → **500「库存不足：剩余 8，需要 999，事务回滚」**
     （⚠️ 这个 500 是故意的，别当成 bug）
   - `GET list`（订单）→ **重新发送** → 还是 **1 条**
   - `GET 商品 getById` id=1 → 重新发送 → stock 还是 **8**
5. 逻辑删除：
   - `DEL 逻辑删除` → id 填 **1** → 发送 → `true`
   - `GET getById`（订单）id=1 → 发送 → **空**
6. 切终端查库（mysql 不在 PATH，用全路径）：
   ```bash
   "/c/Program Files/MySQL/MySQL Server 9.2/bin/mysql.exe" -uroot -p123456 -D backend_learning \
     -e "SELECT id, order_no, quantity, amount, status, deleted, create_time, update_time FROM t_order;"
   ```

**台词（查库这步最关键）**：
> 订单没多出来，库存也没少，两个写操作是原子的。
> （查库后）接口查不到，但库里这行**还在**，`deleted = 1`，`update_time` 也刷新了——这才是逻辑删除的真相。

**预期结果**：库存 10 → 8；失败请求 500 且订单数不变、库存不变；逻辑删除后接口查不到、库里 `deleted=1`

**翻车**：
- 订单 id 不是 1 → 先 `GET list` 看实际 id 再填
- 库存不是 10 或订单已有数据 → 重启应用
- `quantity=999` 返回 200 → 说明库存数字不对，重启

### 段 6 · 收尾（约 30 秒）

**屏幕上**：切到 `docs/课后练习-思路与做法.md` 的踩坑清单

**台词**：
> 总结一下：条件构造器用方法引用更安全；时间字段靠 @JsonFormat 定格式；
> 建表按数据形态选类型、金额用 DECIMAL；批量操作记得配事务；
> 连接池上限要结合实际并发来调；事务保证多个写操作的原子性。
> 另外这次踩了两个坑：
> 一是 `update(Wrapper)` 不带实体时不触发自动填充，得自己 set `updateTime`；
> 二是连接池实验必须在事务内 sleep 才压得出来，普通查询毫秒级就还了连接。
