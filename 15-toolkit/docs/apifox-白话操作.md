# 照着点就行：15-toolkit 在 Apifox 里怎么测

这份文档假设你只会点鼠标。每一步都写死了"点哪里、填什么、看到什么算对"。

---

## 第 0 步：先认清 Apifox 中间那块区域

不管点哪个接口，中间的界面永远是这三层，从上往下：

```
①  POST  /toolkit/xxx  [发送]     ← 请求方式 + 网址 + 发送按钮
②  Params  Body  Headers  ...     ← 一排标签，决定"这次要带什么数据"
③  Pretty  Raw  ...  200  通过     ← 服务器返回的结果
```

**第 ② 排标签怎么选，只有三种情况：**

| 你要干的事 | 点哪个标签 | 然后选什么 |
| --- | --- | --- |
| 参数挂在网址问号后面（比如 `?ticket=abc`） | `Params` | 出来一张两列的表格，填"参数名"和"参数值" |
| 要发一段 `{...}` 文字 | `Body` → 点蓝色 **JSON** | 出来一个文本框，把 `{...}` 粘进去 |
| 要传文件 | `Body` → 点 **form-data** | 出来一行行的表格，**类型那列要改成 File** |

**第 ③ 块怎么判断成功：**

- `"code": 200` 或者绿色的「通过」= 成功
- `400` / `"code": 4xxxx` = 服务器拒绝了。**这在测试里是好事**，说明防护生效了
- `404` = 网址写错了
- 一直转圈或者"连接失败" = 服务没启动，或者 Apifox 的代理没关

**关于复制代码：** 下面所有灰色框里的内容，你要复制的是**框里第一行到最后一行**。像 ` ```json ` 这种开头带三个反引号的，那是排版符号，**绝对不能复制进去**（你上次就是这么贴错的）。

## 第 1 步：先清掉你贴错的脚本

你现在「后置操作」里有两个东西，其中一个把 ` ```js ` 也粘进去了。那是格式符号，贴进去会报错。

删法：点「后置操作」→ 找到那行脚本 → 鼠标移上去，右边出现「…」→ 点它 → 删除。

删掉不影响测试，下面所有步骤都**手动复制结果**，不靠脚本自动记。

## 案例 6：分片上传（你现在卡在这）

### 先解决你刚才那个坑

你截图里 `totalChunks` 是 **21**。这个数字的意思是"这个大文件要切成 21 块"。21 块意味着你得手动点 21 次上传，少一块就合并不了。

**改成 3。**

### 第 1 步：重新登记

1. 左边目录：`15-toolkit` → `案例 6 分片上传` → 点 **init**
2. 上面的 `POST` 和 `/toolkit/chunk/init` 都不用改
3. 点 **Body** → 点蓝色 **JSON**
4. 把框里的内容全选删掉，换成：

```json
{
  "fileName": "test.bin",
  "totalChunks": 3,
  "md5": ""
}
```

5. 点紫色 **发送**
6. 下面出现 `"code": 200`，里面有一行 `"uploadId": "b99385a8a1904f7f94123e3c69e509ff"` 这样的 32 位字符串

**把这串 uploadId 复制下来**，粘到记事本/微信文件传输助手里放着，后面 3 步都要用它。

### 第 2 步：传第 1 块

1. 左边点 **upload**
2. 点 **Body** → 点 **form-data**
3. 表格里填三行（点表格右边「+」加行）：

| 参数名 | 参数值 | 类型 |
| --- | --- | --- |
| `uploadId` | 粘贴刚才那串 32 位 | Text |
| `index` | `0` | Text |
| `file` | 点「选择文件」，随便选一个文件 | **改成 File** |

4. 点 **发送** → 看到 200 就成功了

### 第 3 步：传第 2 块、第 3 块

**别的都不动，只把 `index` 那个值改一下：**

- 把 `0` 改成 `1`，点发送
- 把 `1` 改成 `2`，点发送

（用同一个文件传 3 次没关系，因为第 1 步 `md5` 我们留空 = 不校验内容）

### 第 4 步：看三块齐了没有

1. 左边点 **status**
2. 点 **Params** 标签
3. 表格里：参数名 `uploadId`，参数值 粘贴那串 32 位
4. 发送 → 应该看到：

```json
"uploaded": [0, 1, 2],
"missing": []
```

如果 `missing` 里还有数字，说明对应的那一块没传成功，回去补传。

### 第 5 步：合并

1. 左边点 **merge**
2. **点 `Params` 标签，不是 Body！**（这是这个接口唯一的坑）
3. 参数名 `uploadId`，参数值 粘贴那串 32 位
4. 发送 → 返回一个 `"fileId": "xxx"`

### 第 6 步：把合并好的文件下回来

1. 左边点 **download**
2. 网址最后是 `/toolkit/chunk/download/{fileId}`，**把花括号连同里面的字一起换成**刚才的 fileId，比如 `/toolkit/chunk/download/a1b2c3...`
3. 发送 → 响应区是乱码（正常，是二进制），点右边向下的箭头 ↓ 存成文件
4. 跟原文件比大小，一样就成了

## 案例 2：扫码登录

必须按顺序点，跳步会报错。

1. 点 **create** → 直接发送（这个接口不用填任何东西）
   → 返回 `ticket`（一串编号，复制它）和 `image`（二维码图片）
2. 点 **status** → 点 **Params** → `ticket` 粘贴刚才那串 → 发送
   → `"state": "WAITING"`（等你扫）
3. 点 **scan** → 点 **Params** → `ticket` 粘贴 → 发送
   → `"state": "SCANNED"`（扫了，还没点确认）
4. 点 **confirm** → 点 **Params** → `ticket` 粘贴 → 发送
   → `"state": "CONFIRMED"`，多一个 `token`（登录凭证，JWT 格式）
5. 再点 **status** 发一次 → 也是 `CONFIRMED`

**注意**：`scan` 和 `confirm` 的 ticket 是填在 **Params**（网址后面），不是填在 Body 里。

## 案例 4：短链

### 第 1 步：生成

1. 点 **short-link**
2. **Body** → **JSON**
3. 填：

```json
{
  "url": "https://www.baidu.com",
  "ttlSeconds": 604800
}
```

`ttlSeconds` = 有效期多少秒。604800 = 7 天。**别再填 52 了**，52 秒后链接就死了，你测的时候早过期了。

4. 发送 → 返回 `"code": "esE2FV"` 这种 6 位短码，复制它

### 第 2 步：看它跳不跳（这一步别在 Apifox 里做）

打开浏览器，地址栏输入：

```
http://127.0.0.1:8015/toolkit/s/这里换成你的短码
```

回车。如果跳到了百度首页，就说明短链生效了。

（在 Apifox 里点这个接口会直接跟着跳走，看不到跳转过程，所以用浏览器最直观）

### 第 3 步：看点击数

1. 点 **short-link/{code}**
2. 网址最后的 `{code}` 换成你的短码（比如 `/toolkit/short-link/esE2FV`）
3. 发送 → `"clicks": 1`（你刚才在浏览器访问过一次）

```json
"errors": [
```

### 第 4 步：下载错误明细

返回里有个 `errorFileUrl`，长这样：


4. 发送 → 返回 xlsx，点 ↓ 下载

## 案例 8：开放接口签名

这个最绕，但套路固定：**先问服务器要一个签名，再拿着签名去调业务接口。**

### 第 1 步：要签名

1. 点 **sign/demo**
2. **Body** → **JSON**

```json
{
  "body": "{\"orderNo\":\"SO1\"}"
}
```

注意这一层套一层的引号，**原样复制**，别改。

3. 发送 → 返回四个值，全部复制：

```
appId     = toolkit-demo
timestamp = 1792678402
nonce     = aB3dE9fG
sign      = 3f2a...（64 位十六进制）
```

### 第 2 步：拿签名去调业务接口

1. 点 **sign/order**
2. 点 **Headers** 标签，填四行：

| 参数名 | 参数值 |
| --- | --- |
| `X-App-Id` | `toolkit-demo` |
| `X-Timestamp` | 刚才的 timestamp |
| `X-Nonce` | 刚才的 nonce |
| `X-Sign` | 刚才的 sign |

3. 点 **Body** → **JSON**，**写成一整行**，别换行、别点「格式化」：

```
{"orderNo":"SO1"}
```

4. 发送 → 200，`"message": "签名校验通过"`

**这一步最容易错**：签名算的是「请求体原文」这个字符串。多行展开的

```
{
  "orderNo": "SO1"
}
```

和紧凑的一行 `{"orderNo":"SO1"}` 是**两个不同的字符串**，签名当然对不上，返回 `41052 签名不正确`。两种正确做法：

- **笨办法**：两边都写成一整行，一模一样（demo 里的 `"body"` 也是紧凑的）。
- **省心办法**：在 **sign/order** 的「前置操作」里加一段脚本，拿实际发出去的 body 现算（见下面「第 4 步」），body 怎么排版都行。

另外 timestamp 只有 **5 分钟**有效期（`tolerance-seconds: 300`），demo 放太久再抄会报 `41053 请求已过期`，重新点一次 demo 就行。

### 第 4 步：让脚本自动签名（推荐，可以跳过第 1、2 步）

1. 点 **sign/order** → **前置操作** → 加「自定义脚本」
2. 粘贴下面这段（**不要连 ``` 那三个反引号一起粘**）：

```js
const appId = 'toolkit-demo';
const secret = '3f2a9c1e5b7d4086a1c3e5f7092b4d68';
const ts = Math.floor(Date.now() / 1000).toString();
const nonce = Math.random().toString(36).slice(2, 14);
const body = pm.request.body.raw || '';
const sign = CryptoJS.HmacSHA256(`${appId}\n${ts}\n${nonce}\n${body}`, secret).toString(CryptoJS.enc.Hex);
pm.request.headers.upsert({ key: 'X-App-Id', value: appId });
pm.request.headers.upsert({ key: 'X-Timestamp', value: ts });
pm.request.headers.upsert({ key: 'X-Nonce', value: nonce });
pm.request.headers.upsert({ key: 'X-Sign', value: sign });
```

3. 把 **Headers** 里手填的那四行删掉（脚本会自己加），Body 随便怎么写
4. 发送 → 200

### 第 5 步：试两种作弊

- 把 `X-Sign` 随便改两个字符 → 发送 → **400，签名不正确**
- 把刚才成功的那次**原封不动再发一遍** → **400，重复请求**（同一个 nonce 只能用一次，防重放）

## 案例 9：敏感数据处理

### 第 1 步：建一个客户

1. 点 **customer**（POST 那个）
2. **Body** → **JSON**

```json
{
  "name": "张三",
  "phone": "13800001234",
  "idCard": "11010519491231002X",
  "password": "abc123",
  "level": "vip"
}
```

3. 发送 → 返回一个 `id`，复制它

> 注意：**创建接口返回的是完整手机号**（`13800001234`），这是故意的——刚录进去的数据回显给你核对。脱敏是「查询接口」按角色做的，别在 create 这里判断。

### 第 2 步：查一下，看有没有打码

1. 点 **customer/{id}**（GET）
2. 点 **Params**，**Path 参数**那一行：参数名填 `id`，值填刚复制的 32 位 UUID
   - 参数名这一格**不能空**。空了 Apifox 不知道要替换哪一段，实际发出去会变成 `/toolkit/customer/`，服务器报 `40400 路径不存在：/toolkit/customer`
   - 也不要把花括号一起粘进去（`{c28319...}`），那样会被当成一个普通字符串，报 `41061 客户不存在`
3. 发送 → `"phone": "138****1234"`、`"idCard": "110105********002X"`

**这就是脱敏**：数据库里存的是完整手机号，但普通角色查出来是打码的。

### 第 3 步：换成管理员查

1. 同一个接口，点 **Params**
2. 参数名 `role`，值 `admin`
3. 发送 → 这次出全码 `13800001234`

### 第 4 步：看数据库里到底存的什么

1. 点 **customer/{id}/raw**，网址换成你的 id
2. 发送 → 手机号是一串 Base64 密文，密码是 `$2a$10$...` 这种 BCrypt 散列

**这俩才是真正存进库里的东西**，就算数据库被拖走，也看不出原文。

### 第 5 步：验证密码

1. 点 **verify-password**，网址换成你的 id
2. **Body** → **JSON**，先填错的：

```json
{ "password": "wrong" }
```

3. 发送 → **400，密码错误**
4. 改成 `abc123` 再发 → 200，通过

```json
}
```

3. 发送 → `hits` 是命中的词，`filtered` 是打码后的文本，`highlighted` 带 `<mark>` 高亮
